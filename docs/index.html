When you need more

None of this is needed for the main flow. It is there when a command is not quite right, or fails.

01

Refine it

Not quite right? Add # only .ts files after the command and press your shortcut again. It changes the command instead of starting over.

02

Fix a failed command

Run hsf right after a command fails. You get a corrected version on your next prompt, with what was wrong. Nothing is re-run.

03

Explain any command

hse <request> adds a short explanation, and hsw "<command>" explains a command you found somewhere, before you run it.

04

Fits your setup

The agent is told which tools you have (rg, fd, jq…) and what the project is (pnpm, Makefile targets, compose). Names only, never file contents.

05

Risk you can see

Deletes, force-pushes, overwrites, cloud deletes and download-and-run (curl … | /bin/bash) are flagged in amber or red. Anything else shows Risk: none recognized: no known pattern matched, which is not the same as safe.

06

A check before you run

Missing programs, syntax errors and wrong context (no git repo, no tmux server) show as Check: LIKELY FAIL. It never runs the command.

07

What gets sent

Your request goes to the agent you picked, with your OS, shell and folder (as ~/project, without your user name). Also tool names, project type and git branch, which HEY_SHELL_CONTEXT=0 turns off. No file contents. Nothing is logged on your machine unless you turn history on.

08

bash, zsh and fish

The same shortcut and commands in all three, with commands written for your shell: set -gx in fish, export in bash and zsh.

Choose your agent

hey-shell asks the AI agent CLI you already use and are logged in to, and never runs what comes back. Agents can use their own tools while they answer, so here is exactly what hey-shell restricts for each:

01 · DEFAULT

claude

Claude Code

Text only. No tools, no MCP servers, no saved session.

02

codex

OpenAI Codex CLI

No writes. A read-only sandbox your Codex config cannot loosen. It may read files in the folder while answering.

03 · EXPERIMENTAL

gemini

Google Gemini CLI

Not restricted by hey-shell. Gemini CLI has no documented way to turn its tools off, so this relies on its own defaults.

$ ~/hey-shell/install.sh --agent codex
